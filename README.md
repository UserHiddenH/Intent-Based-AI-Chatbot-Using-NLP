# Intent-Based AI Chatbot (NLTK + Neural Network)
### (with a custom JSON intents dataset)

## Overview

This project implements a **retrieval-based chatbot** that classifies user messages into predefined **intents** and responds with a matching pre-written reply.

The goal of this project is to understand how a simple NLP pipeline works end-to-end — from raw text to a trained neural network classifier — using **NLTK** for language preprocessing and **TensorFlow/Keras** to build, train and run the model.

The bot does not generate text: it predicts the **intent** behind a message (greeting, thanks, help request...), then picks a random response from that intent's list of pre-written replies.

---

## Features

* Custom intents dataset (JSON): 22 tags, each with many varied patterns and several responses
* Text preprocessing with NLTK (tokenization, lowercasing, lemmatization)
* Vocabulary construction from all training patterns
* Bag-of-words text representation
* One-hot encoding of intent classes
* Fully connected neural network (Keras Sequential model)
* Dropout layers to reduce overfitting
* SGD optimizer with momentum and Nesterov acceleration
* Data serialization with Pickle (vocabulary + classes)
* Trained model saved in the native Keras format (`.keras`)
* Confidence threshold and fallback response for unrecognized messages
* Random response selection for more natural-sounding replies
* Real-time intent prediction from user input in the terminal

---

## Network Architecture

```
Input Layer (bag-of-words, size = vocabulary length)
        │
        ▼
Dense Layer (128 neurons)
      ReLU
        │
     Dropout (0.5)
        │
        ▼
Dense Layer (64 neurons)
      ReLU
        │
     Dropout (0.5)
        │
        ▼
Output Layer (size = number of intents)
      Softmax
```

Each output neuron represents one intent tag (e.g. `greetings`, `goodbye`, `thanks`...).

**Training configuration:**

* Loss: categorical cross-entropy
* Optimizer: SGD (learning rate 0.01, momentum 0.9, Nesterov)
* Epochs: 200
* Batch size: 5

---

## Dataset

The project uses a **custom-built `intents.json` dataset**, structured as follows:

* **Tags:** 22 intent categories (greetings, goodbye, thanks, help, compliment, complaint, jokes, bot identity, and more, including a `fallback` category)
* **Patterns:** example phrases a user might type for each intent, mixing formal and informal language, slang, contractions and common abbreviations
* **Responses:** possible bot replies for each intent, picked at random at runtime

Before training, all patterns are:

* Tokenized into individual words
* Lowercased and lemmatized with NLTK's `WordNetLemmatizer`
* Converted into bag-of-words vectors representing the full training vocabulary

The same preprocessing is applied to user messages at runtime, so training and inference stay consistent (e.g. `Hello` and `hello` are treated identically).

   ```bash

   ```


## Training

The network is trained on bag-of-words vectors (`X`) mapped to one-hot encoded intent labels (`y`).

During training, the following operations are performed:

1. Load and preprocess `intents.json`
2. Build the vocabulary and the class list
3. Convert each pattern into a bag-of-words vector
4. One-hot encode the corresponding intent
5. Shuffle the training data
6. Train the Keras model using the SGD optimizer
7. Save the trained model and the serialized vocabulary/classes for reuse

---

## How a Message Is Processed

1. The user message is tokenized, lowercased and lemmatized
2. It is converted into a bag-of-words vector using the saved vocabulary
3. The model outputs a probability for each intent
4. Predictions below the confidence threshold, or messages containing no known word, trigger the `fallback` intent
5. A random response from the predicted intent is displayed

## Results

The trained model can:

* Predict the intent behind new, unseen user messages
* Handle variations in casing, wording and politeness level
* Select a fitting response from the matching intent's response list
* Fall back to a generic reply when a message is not understood
* Hold a simple real-time text conversation in the terminal

---

## Limitations

* The bot can only return pre-written responses (it does not generate text)
* Each message is classified into a single dominant intent, so messages containing several intents (e.g. "hello, I need some help") are reduced to one
* Words unknown to the vocabulary are ignored, so heavy typos can hurt recognition
* Lemmatization uses NLTK's default noun mode, so conjugated verbs are often left unchanged
* Quality depends directly on the diversity and balance of the patterns in `intents.json`
